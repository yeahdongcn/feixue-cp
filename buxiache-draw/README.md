# 画地为牢 · v3

> 绳长就是周长。你圈住什么，就只剩什么。

一个单 HTML 的 Canvas 2D 游戏，双击 `index.html` 就能玩，手机浏览器也能玩。
没有图片、没有字体文件、没有音频文件、没有 CDN：画面和声音都在运行时生成。

**验收状态（2026-11-14）**：`levels / guard / play` 全绿；1280×800、390×844、320×568、844×390 四档 × 五个画面全部 **0 个版式问题、0 条 console 报错**。
这一轮做的是**原创配乐 + 六站年代光 + 看得见的反馈**：60 BPM 的 A 小调动机、四件合成乐器、前瞻调度、1.2s 淡入、1.5s 换站交叉淡化；六站各有一套纸面温度 / 时代色 / 章节水印；画的过程中圈内物件会亮；名字有墨线牵回自己的圈；失败的话浮在圈外最近的一块空地。见「这一轮：年代光与原创配乐」。
上一轮是验收 + 收尾（名字离圈、线穿字、放手太淡、横屏排成一列），见「验收这一轮」；再往前是构图 / 提示条 / 标签，见「上一轮：构图、提示条、标签」。

## 怎么玩

按住拖动，在地上画一条线。**把线绕回来接上自己**，圈就封住了。

- 圈里的东西留下，圈外的永远留在外面
- 绳子长度就是这一圈能画多长，**每一站都在变短**
- 每一站有最低要求（如“圈住 3 样”），圈不够就作废、这一笔重来
- 短按/松手没接上不会锁死，直接再画一笔即可；桌面按 `R` 可清掉当前这一笔
- 桌面按 `M` 或点右下角 `声音 · 开/关` 静音；站牌上按空格 / 回车开始

## 这一轮：年代光与原创配乐

### 1. 同一张纸，六种光

不是给六站换六套 UI 配色，而是让纸本身换温度：

| 站 | 时代色 | 纸面 | 章节水印 | 配器 |
|---|---|---|---|---|
| 2006 宿舍 | `#ffc98a` 暖橙 | 棕褐 | 宿舍 | 音盒 + 弦垫 + 低音 |
| 2007 台上台下 | `#ff9e8a` 旧粉 | 玫瑰褐 | 台上台下 | 钢琴 + 弦垫 + 心跳低鼓 / 轻噪声 |
| 2014 小场子 | `#d5c489` 旧金 | 橄榄褐 | 小场子 | 音盒 + 钢琴 + 一下底鼓 |
| 2020 麦克风前 | `#b9c6d8` 冷灰蓝 | 蓝炭 | 麦克风前 | 钢琴 + 长弦垫 + 很轻的点击 |
| 2026 四千米 | `#a9d2dc` 冰青 | 冰炭 | 四千米雪 | 高音盒碎片 + 冰点噪声 |
| ???? 牢 | `#cec1ad` 骨白 | 灰褐 | 牢 | 只剩动机尾巴 + 低音 + 一下心跳 |

- 颜色只染 HUD 年份、绳长、光池、格线和章节水印；名字和绳子仍是暖墨，冷纸上反而更清楚。
- `drawWatermark()` 把章节名直接压在纸里，不加滤镜、不每帧做模糊；桌面 4.5%（末章 8%），窄屏 6.2%（末章 9.6%）——同一行字在 390 宽上只有桌面的 1/3 宽，不提一档就看不见。末章是一个大字「牢」，在 26 个淡年轮后面。它不是标题，是纸的一部分。
- 纸的温度只在 `PAPER_STOPS` 里换四个渐变色，不改布局、不改关卡。

### 2. 圈内的东西会先亮

以前画的时候只有右上角的数字在变。现在每一帧把当前路径和物件做一次 `inPoly`：

- 已经圈进来的：环变暖、加 1.7px 内亮、轻微呼吸、身后一团 56px 暖光；名字同步转暖。
- 还没圈进来的：保持冷白，明显退到后面。
- 圈够了：右上角从 `还差 N 样` 变成 `够了 · 松手封口`，绳长数字转暖，起点环亮起；只亮一个小环，真正回到起点才叠第二圈，避免和物件自己的圈叠成一团。
- 失败：`failAnchor()` 在圈的上/下/右/左四个空位里按“离物件最远”挑一个，浮字落在那里，不再只贴在屏幕最下面，也不再压在圈中间的物件上。

### 3. 名字有墨线牵回自己的圈

`planLabels()` 原来只保证“盒子不压圈”，4 字名字被推到 80–100px 外时看起来像一条无主说明。这一轮给所有 `lead` 的标签补一条 1.1px 的墨线：从圈的边缘出发，落在名字盒最近的点，起点一个小墨点。封口态、放手态、实时态各有自己的透明度；名字的暗色描边 + 柔光仍是底层保障。

### 4. 原创配乐：一句动机，六种“剩下多少”

- **速度**：60 BPM，八分音符一步 = 0.5s，8 步一小节 = 4s。只此一作是 60（RPG 72 / runner 128 / 各执一词 66）。
- **动机**：`A4 C5 E5 D5 C5 B4 A4 G4`（MIDI `69 72 76 74 72 71 69 67`），A 小调，每个音占一个八分音符（0.5s）、连奏。六站共用；只改变“留下哪些音”和“谁在说”。
- **六种配器**：2006 音盒（高八度）+ 弦垫；2007 钢琴 + 弦垫 + 心跳低鼓/轻噪声；2014 音盒与钢琴齐奏 + 一下底鼓；2020 钢琴 + 四小节一换的长弦垫；2026 只剩高音盒碎片和冰点噪声；???? 只剩动机最后两个音、弦垫 A2/E3/A3、低音 A1 和一下心跳。
- **四件乐器全部现场合成**：
  - 钢琴：sine + triangle（detune 4 cents），attack 0.004s，decay 0.9s
  - 弦垫：每个音两条 detune ±6 cents 的 sawtooth，900Hz 低通，attack 0.6s
  - 音盒：sine + 高八度 sine（0.2），包络 0.25s
  - 鼓：底鼓 sine 120→45Hz / 0.17s；点击是白噪声 + bandpass + 0.055s 包络
- **调度**：`setInterval(musicTick, 25)` + `LOOKAHEAD = 0.12`，所有音符按 `AudioContext.currentTime` 预约，没有逐音符 `setTimeout`。
- **总线**：`master 0.62`（音效）/ `musicOut 0.18`（配乐），都先过 `muteGate`；进游戏后 `musicOut` 0→0.18 线性 1.2s；换站旧场景 1.5s 淡出、新场景 1.5s 淡入；旧场景 1.75s 后回收。
- **不突然出声**：首屏不创建 AudioContext；第一次点击/按键才 `resume`。先按 `M` 或先点声音按钮静音，不会先漏一声。
- **静音**：`M` 键 + 右下角按钮，状态写 `localStorage`，刷新后保持。
- **没有任何音频文件**：没有 `<audio>`、没有 `new Audio()`、没有 mp3/wav/ogg；也不引用任何真实歌曲的旋律。

### 5. 更容易读的结算

- 分数从 `14 / 12` 一行改成两个“数字 + 单位”的竖排：`14 样圈住`、`12 样放手`，中间一条细分隔线，`共 26 样` 靠右。
- 数字的 line-height 放到 1.42：宋体的字面比行框高，1.02 时 `scrollHeight` 会比 `clientHeight` 大 9px，探针会报“文字溢出”（这是真的裁字风险，不是误报）。
- 物件圈从 24px 提到 28px（桌面/390 竖屏）；320 宽纸太窄，仍退回 24px，避免圈压纸边。
- 320×568 和 844×390 两档新增/收紧了结算卡压缩规则：320 隐藏尾注，整卡 531px 高（上下各 18px）；844×390 把标题/分数/年份/分享句压进 370px（上下各 10px），按钮仍是 46/44px。

## 关键设计

### 1. 手上的分量

- **笔宽跟着手速走**：慢下来墨会堆粗，快起来线会拉细；起笔收笔有锥形。
  实测一笔忽快忽慢的圈，笔宽在 `0.55×`–`1.32×` 基准宽之间，出现 10 档。
- **不做位置缓动**：`pointermove` 处理 `getCoalescedEvents()`，笔尖就在手指/鼠标的位置。
- 桌面端多一个**笔尖停靠点**（亮点 + 细环），触屏不显示，避免留下“幽灵笔尖”。
- **WebAudio 现场合成**：落笔的纸面摩擦、封口的三音和弦 + 低频、失败的低频、按钮轻点；配乐是另一条 0.18 的总线，60 BPM 的原创动机，见上一节。
  声音在第一次手势时才解锁；手机有 `navigator.vibrate` 时封口/失败各给一次短震。

### 2. 封口 / 失败的反馈层次

封口这一下是分层的，不是一个大特效：

1. 收口处一颗结 + 一圈 0.9 的白闪
2. 6.5px 衰减的镜头震动（只震画布，UI 不抖）
3. 34 颗火星 + 9 颗上浮余烬（原来那两圈同心冲击波删了——它和物件圈、物件光环叠在一起，正是"像扫描仪"的来源）
4. 圈内亮起暖光，圈外压暗，边界加一圈细光；**光池跟着圈走**，不再钉在屏幕中心照亮一块空地
5. 圈住的物件按 85ms 间隔逐个亮起：光晕鼓一下 + 爆小火星，不再画第二圈扩散环
6. 底部安全区一行 `封住了`（数量已经在右上角，不再重复），1.35s 后用**墙钟**推进下一站（掉帧不会把等待拖长）

失败是另一套：红闪、4.5px 震动、20 颗余烬、红色 toast，780ms 后真正重置这一笔。

### 3. 光、层次、留白

- **整屏是一张纸**：纸边内缩 14/20px，18px 四角刻线，格子在 46–78px 之间取接近正方形的一档。纸边画在暗角**之上**，所以屏幕永远有“画框”，不会塌成黑洞
- **取景跟着每一关走**：`fitView()` 量出本关所有物件的包围盒，把包围盒等比放进安全区、居中（`MIN_SPAN=360` 兜住末章那个单点）。1280×800 下缩放从固定棋盘的 `0.62` 提到 `1.16–1.35`，手机上从 `0.37` 提到 `0.58`
- 安全区让开顶部 HUD 和底部提示条，并且**夹在纸边以内**；两块屏幕短到 390 高时，物件圈会自动缩到 15–19px，两个圈不会叠在一起
- 背景不是纯黑：暖纸底色 + 跟着本关重心走的光池 + 40 颗缓慢上浮的尘埃 + 固定种子的纸面颗粒
- 物件只有**一个圈** + 一个光晕 + 半粗 13px 名字。名字由 `planLabels()` 逐个试方向放：优先朝圈内/重心，其次上下左右，避开别的名字、别的物件和纸边
- 名字有三层“垫”：`3px` 暗色描边 + 一层同色柔光（封口后线从字后面过也不会渗光）+ 离自己的圈至少 `10px` 的硬间距；封口后还会避开那圈线本身
- 圈外变暗后仍补一层淡格子和纸边，留白处还是“纸”，不是黑
- 前五站留下的东西在末章只留字形不抢“你自己”：以“你”为圆心重排成一圈淡年轮（手机少放一半），中心 92–126px 让空
- 章节卡是场景里的一块**站牌**：板面、光、物件仍在四周；站牌出现时 HUD 和声音按钮一起让位
- 结算卡是一张可以直接截图的深色卡：标题、称号、分数、年份格、一句可复制的话、两个按钮

## 第三阶段验收修了什么

1. **结算卡在小屏 / 横屏被裁**
   - 320×568：卡高超过可视区，按钮底边被裁 7px、尾注整行出屏。
   - 844×390：结算卡被 `max-height` 截到 350px，分数、分享句、两个按钮全部出屏。
   - 修法：保留 390×844 与桌面的原版式；新增 `≤360px 宽` 和 `≤520px 高` 两套压缩规则，重排标题/分数/年份格/分享句的间距，并在矮屏隐藏非必要的尾注。现在 320×568 卡高 531px（上下各留 18px），844×390 卡高 370px（上下各留 10px），按钮完整可点（竖屏 46px / 横屏 44px，均 ≥44px 触控下限）。
2. **声音按钮可见但点不到**
   - 章节卡打开时 `#snd` 没有被 `body.card-open` 隐藏，但 `#card`（z-index 5）盖在 `#ui`（z-index 2）上面。结果按钮看起来还在，点下去却是“开始游戏”。
   - 修法：站牌出现时声音按钮随 HUD 一起隐藏；进入可玩状态后再出现。
   - 同时把声音按钮从 37px 高提到 **44px**（触控目标下限），手机端把它上面的提示文字抬高 10px，留出 8px 间距。
3. **复验**：上述两个问题修完后，320×568 与 844×390 的五个画面也变成 0 问题 / 0 报错；390×844 与 1280×800 的版式数字没有回退。

## 验收这一轮：看图复核 + 只修看得见的

先跑测试（全绿），再按 1280×800 / 390×844 两档截图逐张看，另外补了 320×568 与 844×390。
> 下面 10.2px / 9/30 两组数是上一轮 24px 圈径时量的；这一轮圈径放大到 28px（≤360 宽仍是 24px），`test/levels.js` 重新跑过全绿，但这两组没有重测。
上一轮那六条**确认在画面里生效**：整屏一张纸、提示条贴底、13px 半粗名字、右上角是唯一出处、扫描仪痕迹没了、绳长有分母。
但盯着图看，还有四处是真的没改好（数字都是这一轮用真实 `planLabels()` 量出来的）：

1. **名字贴着自己的圈**（旧算法只在斜向摆放时漏判）
   - `planLabels()` 用“圆心到标签锚点的距离 = R + 17”当间距，可斜着放时盒子是从锚点往一边长出来的，实际离圈边只剩 5–7px。
   - 量了 5 档 × 6 关共 30 个封口画面：旧算法 **16/30 个画面有名字离圈 < 8px，最紧 5.6px**（390 上「一支话筒」的下沿干脆压在麦圈上）。
   - 改法：新增 `boxGap()` 量“盒子最近点到圆心”的距离，不够 `R + CLEAR(10)` 就沿候选方向把盒子推出去，推完再判分。
   - 现在：**0/30 个画面 < 8px，最紧 10.2px**。
2. **线从字中间穿过去**
   - 封口后绳子和名字抢同一块地方：30 个封口画面里 **19 个**至少有一个名字被线穿过，390 上「宿舍门牌」的「宿」直接被亮线切开。
   - 两级修法：① 名字描边外再垫一层同色柔光（`shadowBlur 7`），线只在字后面，不在笔画之间渗光；② 封口后绳子是静止的，把路径传进 `planLabels()`，线段与标签盒相交就罚分——**画的过程中不传**，否则名字会跟着手指抖。
   - 现在：**9/30**，且剩下的是“圈就那么大，名字只能压在边上”的取舍。
3. **「放手」的名字太淡**
   - `#a89d8a` 再乘 `.62` 和 `.98`，压在 `#221a12` 上是 **3.26:1**；13px 宋体在这个对比度上要凑近看。
   - 圈和字形继续退到暗面，只把名字提一档到 `#d4c9b3`：实测 **4.4–4.8:1**。
4. **横屏 844×390 三个名字排成一列**
   - 名字之间原来只判“有没有重叠”，三个盒子各差 9px 也算通过，看起来像一段和圈无关的说明。
   - 改法：把标签之间的判定从“重叠面积”换成“扩 12px 后的盒子重叠面积”，并按面积罚分。
   - 现在横屏是「宿舍门牌」在上、「一支话筒」在右、「一张车票」在下，各自贴着自己的圈。
5. 顺手：手机结算卡按钮 44 → 46px（原来已经达标，只是多留 2px 余量）。

**这一轮没有动关卡坐标，也没有动绳长。** 构图那两条限制还在，见「已知限制」。

## 上一轮：构图、提示条、标签

用户看着 `02_play_old.png` / `04_sealed_old.png` 提了六条，逐条落到的改法：

1. **构图严重浪费：圈只占屏幕四分之一，右边 40% 全空**
   - 根因是取景固定：`s = min(w*0.94, h*0.78)/1000`，1000×1000 的棋盘放在一千多像素的屏幕上，物件的包围盒只占中间一小块，右边和下半屏全是空盘。
   - 改法：`levelBox()` 量本关物件包围盒 → `fitView()` 等比放进安全区、居中。棋盘不再是一个正方形，而是**整块屏幕的一张纸**（纸边 + 四角刻线 + 方格）。
   - 数：1280×800 缩放 `0.62 → 1.16`（物件最近间距 176px），390×844 `0.37 → 0.58`（85px），1920×1080 `0.84 → 1.82`。`test/levels.js` 新增“至少一个方向填满安全区 75%”的回归断言。
2. **提示条压在物件上**
   - `#toast` 从 `top:50%; translateY(-50%)` 挪到**贴底部的固定安全区**（桌面 `bottom:84px`，≤560px 宽 `bottom:112px`），并且 `layout()` 会量 `#hint` / `#snd` 的真实位置来定这个值。
   - 封口时 toast 只写 `封住了`：数量已经在右上角，不再重复第三遍。
3. **11px 的标签压在发光的圈线上，读不清**
   - `600 13px` 半粗 + 3px 暗色描边（`strokeText` 垫底）、亮一档的字色；细宋体 13px 在暗底上会发灰，第一版加了描边还是糊，看图才发现是字重不够

## 实现要点

- 全部 Canvas 2D，无依赖、无图片、无字体文件（用系统中文字体）
- 封口有两种判定：线条自己交叉（`segHit` + 截断到交点），或几乎绕满一圈回到起点
- 用累计转角（`G.turn`）防止“起手一个小弯就被误判成封口”
- 取景：`levelBox()` 量包围盒 → `fitView()` 等比放进安全区并居中；物件仍画在屏幕空间，圈半径按屏幕密度在 15–28px 之间自适应（≤360 宽退回 24px，手机上不会缩成看不清的小点，矮屏也不会两个圈叠在一起）
- 画的过程中有一条虚线从笔尖连回起点，靠近时起点环会亮、会呼吸；松手会闭成什么样一眼能看到
- 线条是逐点算宽后拼出的多边形带（不是恒定 `lineWidth` 的 stroke），所以粗细能连续变化
- 章节推进、失败重置、分享复制都不依赖 `location.reload()`；“再画一次”走 `loadLevel(0) + showCard(0) + 清空记录`
- 结算卡在窄屏/矮屏只压间距和字号，不隐藏分数、分享句和两个按钮；只有横屏的尾注（“截屏保存这张卡…”）因高度不足隐藏

## 已知限制

- **这一轮是人眼复核的**：每一步都是“截图 → 看图 → 改”，1280×800 与 390×844 两档逐张看（站牌 / 开局 / 失败 / 封口 / 结算），另外补看了 320×568 与 844×390。**声音只验证到调度和数值**：首屏无 AudioContext、第一次手势后 `resume`、1.2s 后 `musicOut=0.18`、换站两个场景交叉、静音写/读 localStorage、无 console 报错；混音平衡和音色是否“好听”仍需要人耳，尤其手机小喇叭上 0.18 的总线可能偏轻。
- **名字仍可能被线穿过（9/30 个封口画面）**：封口后已经会让名字避开绳子，但圈本身就只有 130×160px（手机），名字又必须挨着自己的圈，有些位置确实无解。现在靠“描边 + 柔光”保证可读，不保证不压线。
- **画的过程中不避线**：路径每帧都在变，若按实时路径排名字，名字会跟着手指抖。这一条是故意的取舍。
- **名字可能横穿别人的圈（4/30）**：都是 320 / 横屏这种“五个圈挤在 240px 里”的版式；罚分能逼它换方向，但换不了不存在的位置。
- **`????` 是设计，不是缺数据**：第六站是“现在”，没有年份。站牌、HUD、结算卡六格里都写 `????`。
- **配乐是 4 秒一句、四句一循环，不是完整编曲**：六站共用一句 8 音动机，靠 mask、配器和低音让“剩下多少”变化；没有 A/B 段、没有终止式，循环感是有意的（像记忆在原地打转）。要更长的发展，得再写第二动机，这一轮没做。
- **六种纸温在低亮度屏上会很像**：2020/2026 的冷纸和 2006 的暖纸在 iPhone 低亮度、夜间模式下差别会缩小；时代色主要靠 HUD 年份、绳长和章节水印辨认，不靠纸色单独承担。
- **封口后的圈子仍然偏画面左侧，为什么**：取景已经按包围盒放到最大了——1280×800 下物件包围盒占安全区高度的 **86%**，但只占宽度的 **48%**。原因是比例对不上：安全区是 1220×562（2.17:1），而 2006 这一关的包围盒是 510×420（1.21:1）。再放大只会让上下两件（磁带 / 灯牌）出屏。圈本身（三件套）只有 270×300 世界单位，封口后在 1280 上是 280×330px（屏宽的 22%），在 390 上是 160×185px（41%）。
  要让它真的铺满宽度，只有两条路：把物件坐标横向拉开（同时重算每关绳长，约束 `1.15×A ≤ rope ≤ 0.97×B`），或者在封口瞬间把镜头推近到圈上（那套粒子/涟漪是按屏幕坐标存的，得先改成世界坐标）。两条都是改设计，我没有偷偷做。
- **手机竖屏上下仍留白**：本关布局是横向的（510×420 世界单位），竖屏只能按宽度取景。实测 390×844：五个物件的外廓只有 y 253–543（290px），安全区是 y 108–732 —— 上下各空约 145px / 190px，物件只占屏幕高度的 **34%**（安全区高度的 46%）。旋转取景能多填 40%，但那会让手机和桌面的物件朝向不一致，这一轮没做。
- **390 竖屏上封口后的圈贴着左边纸边**：2006 这一关要圈的三个（门牌 / 话筒 / 车票）在世界坐标 x 310–470，整关五件是 x 310–820；取景按**五件**的包围盒居中，圈子就落在左边。实测圈的最左边到纸边只剩约 9px。这不是版式的错（五件的包围盒已经放到最大），是关卡坐标本身偏左。
- **没有真机**：触控用 Playwright 的 `hasTouch` 模拟（tap 声音/复制/重开都通过），但真实手机的触控延迟、低端机帧率、iOS Safari 的 `clipboard`/`vibrate` 行为仍未实测。
- **超宽屏和 320×480 以下未验证**：本轮补了 320×568 与 844×390；3440×1440 之类超宽屏，以及高度低于 480 的窗口没有专门版式。
- **320×568 是“能玩”而不是主目标**：`levels.js` 复算物件最近 67px、覆盖 83%，五个画面探针 0 问题；但只有 4.7 英寸级别的纸，名字/圈的呼吸空间仍然最紧（见上面的 4/30）。
- **极尖急转的笔画可能让多边形带轻微自交**：截图夹具的圆弧路径覆盖不到这种手绘路径，需要真人乱画测试。
- **分享卡仍是“截图分享”，不是导出 PNG**：没有 `canvas.toDataURL` 下载按钮；要直接发图得先截屏。
- **`file://` 下 clipboard 因浏览器而异**：本机 Chromium 回读“已复制”；被拒时会退到 `execCommand`，再不行提示“长按上面那句话”。
